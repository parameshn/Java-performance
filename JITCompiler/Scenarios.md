## Java Compiler and JVM Scenarios

### Scenario 1: Same Compiler, Different JVMs

You compile the application once and run it on different platforms.

```text
Java Source (.java)
        │
        ▼
      javac
        │
        ▼
Java Bytecode (.class)
        │
        ├────────► Windows JVM (x86)
        │                 │
        │                 ▼
        │          x86 Machine Code
        │
        └────────► macOS JVM (ARM)
                          │
                          ▼
                   ARM Machine Code
```

- The bytecode is the same.
- Each JVM generates machine code for its own platform.
- This is Java's **Write Once, Run Anywhere** principle.

---

### Scenario 2: Same Bytecode, Different JDK Versions

```text
Java Bytecode
       │
       ├────────► JDK 8 JVM
       │                 │
       │                 ▼
       │        Native Machine Code
       │
       └────────► JDK 21 JVM
                         │
                         ▼
            More Optimized Machine Code
```

- Both JVMs execute the same bytecode.
- A newer JDK may generate better optimized machine code because its JIT compiler has improved.

---

### Scenario 3: Different CPUs

```text
Java Bytecode
       │
       ├────────► Intel JVM
       │                 │
       │                 ▼
       │          x86 Instructions
       │
       └────────► ARM JVM
                         │
                         ▼
                  ARM Instructions
```

- The bytecode does not change.
- The generated machine code is different because the CPUs use different instruction sets.

---

### Scenario 4: Different Java Compilers, Same JVM

```text
Java Source
      │
      ├────────► javac (JDK 17)
      │                 │
      │                 ▼
      │            Bytecode
      │
      └────────► javac (JDK 21)
                        │
                        ▼
                   Bytecode
                        │
                        ▼
                  Same JVM
```

- Different versions of `javac` may generate slightly different bytecode.
- The JVM executes whichever bytecode it receives.

---

### Scenario 5: Older Compiler, Newer JVM

```text
javac (JDK 17)
        │
        ▼
Java Bytecode
        │
        ▼
JVM (JDK 21)
        │
        ▼
Native Machine Code
```

- This is a common scenario.
- Newer JVMs are backward compatible and can execute older bytecode.

---

### Scenario 6: Newer Compiler, Older JVM

```text
javac (JDK 21)
        │
        ▼
Java Bytecode
        │
        ▼
JVM (JDK 17)
```

- This generally does **not** work.
- The older JVM may not understand the newer bytecode version.

Typical error:

```text
UnsupportedClassVersionError
```

---

### Scenario 7: Compile Once, Run Everywhere

```text
Java Source
        │
        ▼
      javac
        │
        ▼
Java Bytecode
        │
        ├────────► Windows JVM
        ├────────► Linux JVM
        ├────────► macOS JVM
        └────────► Docker JVM
```

Each JVM compiles the bytecode into machine code suitable for its own operating system and processor.

---

## Summary

| Compiler (`javac`) | JVM                         | Result                                       |
| ------------------ | --------------------------- | -------------------------------------------- |
| Same               | Different                   | Same bytecode, different machine code        |
| Different          | Same                        | JVM executes the generated bytecode          |
| Older              | Newer                       | ✅ Supported (backward compatibility)         |
| Newer              | Older                       | ❌ Usually not supported                      |
| Same               | Different CPU architectures | Same bytecode, platform-specific native code |

### Key Points

- **`javac`** compiles Java source code into **platform-independent bytecode**.
- The **JVM** executes the bytecode.
- The **JIT compiler**, which is part of the JVM, converts frequently executed bytecode into **platform-specific native machine code**.
- Therefore, **Java's portability comes from bytecode**, while **performance comes from the platform-specific JIT compiler**.
